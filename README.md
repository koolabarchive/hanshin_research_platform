# 한신 리서치풀

한신대학교 일반대학원 연구자를 위한 연구참여자 모집 플랫폼입니다.

참여자는 대기풀에 조건을 한 번 등록해 두면 맞는 연구가 열릴 때 안내를 받고, 연구자는 참여자의 이름과 연락처를 모른 채 가명 ID로만 모집·안내·보상을 처리합니다. 모든 연구는 연구윤리지원팀이 IRB 승인을 확인한 뒤 공개됩니다.

## 구조

서버가 없습니다. Firebase 무료(Spark) 요금제로 동작합니다.

```
브라우저(web/ → public/)  ── Firebase Auth ──▶  로그인·이메일 인증
                          ── Firestore ─────▶  데이터 (보안 규칙 아래에서 직접 읽고 씀)
```

- **화면**은 정적 파일입니다. Firebase Hosting에 올립니다.
- **접근 통제는 `firestore.rules`가 전부 맡습니다.** 누가 무엇을 읽고 쓸 수 있는지는 이 파일을 보면 됩니다.
- 서버가 없어서 **이메일·문자는 보내지 않습니다.** 초대·안내·일정·보상 알림은 모두 플랫폼 안의 알림함으로 전달되고, 참여자는 로그인해야 확인할 수 있습니다. 가입 인증 메일과 비밀번호 재설정 메일만 Firebase Auth가 직접 보냅니다.

## 누가 무엇을 볼 수 있나 (규칙 요약)

| 정보 | 참여자 본인 | 연구자 | 연구윤리지원팀 |
| --- | --- | --- | --- |
| 이름·이메일·휴대전화 (`users/{uid}/private`) | O | X | 한 건씩 열람(상품권 발송용) |
| 매칭 정보 (`pool/{uid}`): 출생연도·성별·신분·학과·관심 분야 — 이름·연락처 없음 | O | 확인된 연구자만 | O |
| 참여 기록 (`enrollments`) | 자기 것 | 자기 연구의 것: 가명 ID·신분·연령대·번호 끝 4자리·설문 응답 | X |
| 전자서명·동의서 사본 (`enrollments/{id}/private`) | O | X (동의 일시만) | X |
| 알림함 (`messages`) | 자기 것 | X (쓰기만: 자기 연구의 초대·참여자에게) | X (쓰기만) |
| 이수증·IRB 통지서 (`files`) | - | 본인이 올린 것 | O |

**알아 둘 점: 확인된 연구자는 대기풀의 매칭 정보를 한 건씩 읽을 수 있습니다.** 서버 없이 조건에 맞는 인원을 세고 초대하려면 연구자의 브라우저가 읽어야 하기 때문입니다. 이름·연락처는 들어 있지 않지만, 작은 학과에서는 출생연도·성별·학과 조합만으로 개인이 짐작될 수 있습니다. 화면은 인원수와 분포만 보여 주지만, 규칙상 읽기 자체는 허용되어 있습니다. 이를 막으려면 Functions(Blaze 요금제)가 필요합니다.

규칙이 직접 막는 것들:

- 연구자는 스스로 연구를 공개하거나 연구자 확인 표시를 바꿀 수 없습니다. 심사 중·공개된 연구의 내용도 고칠 수 없습니다(공지, 리마인더 설정, 완료 인원 집계만 가능).
- 초대는 그 연구의 담당 연구자가, 대기풀에서 안내를 받고 있고 조건에 맞는 사람에게만 만들 수 있습니다. 알림은 자기 연구에 초대했거나 참여 중인 사람에게만 보낼 수 있습니다.
- 참여자는 조건(나이·신분·성별·학과)에 맞고 모집 기간 안인 연구에만 신청할 수 있습니다. 신분·출생연도는 가입 후 바꿀 수 없습니다.
- 재학생·교직원 신분과 연구자 가입은 학교 메일(@hs.ac.kr)이어야 하고, 이메일 인증 전에는 연구 목록을 읽거나 안내 대상이 될 수 없습니다.
- 동의는 가입한 이름과 같은 서명이 함께 저장될 때만, 예약은 정원이 남아 있을 때만(예약 수 +1과 참여 기록 변경이 한 트랜잭션), 철회는 자리 반환과 함께만 됩니다.
- 상품권 지급 처리는 발송 요청(`rewards`)이 함께 만들어질 때만 됩니다. 발송 완료 표시는 관리자만 합니다.
- 관리자 지정(`admins/{uid}`)은 콘솔이나 스크립트로만 합니다.

규칙이 아니라 화면 코드가 지키는 것(악의적인 연구자가 화면을 우회하면 어길 수 있음): 한 사람에게 가는 모집 안내 주 3회 제한, 연구당 직접 안내 하루 3회 제한, 연구 초안의 세부 형식, 처리 기록 남기기. 연구자는 학교 메일 인증과 연구윤리지원팀 확인을 거친 사람으로 한정됩니다.

## 로컬에서 실행 (에뮬레이터)

Node.js 22 이상과 Java가 필요합니다. 터미널 두 개를 씁니다.

```bash
npm install
npm run emulators
```

```bash
npm run seed
```

http://localhost:3000 을 열고 `로그인`을 누르면 시연 계정(참여자·연구자·관리자) 버튼이 보입니다. localhost에서 열면 실제 프로젝트가 아니라 에뮬레이터에 붙습니다. 시연 데이터는 모두 가상입니다. 새로 가입해 볼 때 필요한 이메일 인증 링크는 에뮬레이터를 띄운 터미널에 출력됩니다.

- 화면 코드(`web/`)를 고치면 `npm run build`로 `public/app.js`를 다시 만듭니다.
- 테스트: 에뮬레이터를 내린 상태에서 `npm test` (규칙 테스트 9개, 매칭·검증 테스트 7개)

## 실제 프로젝트에 올리기

**아래 절차는 실제 프로젝트에서 확인하지 못했습니다.** 이 저장소의 검증은 모두 에뮬레이터에서 했습니다.

배포 대상은 이 플랫폼 전용 프로젝트 `hsresearch-d0c1a`입니다(`.firebaserc`, `web/firebase-config.js`). `firebase deploy`는 대상 프로젝트의 Firestore 규칙을 통째로 바꾸므로 다른 앱이 쓰는 프로젝트에는 배포하지 않습니다.

1. 규칙과 색인 배포:

   ```bash
   firebase login
   firebase deploy --only firestore
   ```

2. 화면 배포: `npm run build && firebase deploy --only hosting` → `https://hsresearch-d0c1a.web.app`
   - 자동 배포: 맥북의 프로젝트 폴더에서 `firebase init hosting:github`를 한 번 실행해 배포 권한을 저장소에 등록하면, 그 뒤로는 `main`에 올라올 때마다 `.github/workflows/firebase-hosting-merge.yml`이 빌드해서 배포합니다. 보안 규칙은 자동 배포하지 않습니다.
3. 관리자 지정: 콘솔의 Authentication에서 연구윤리지원팀 계정을 만든 뒤, Firestore에 `admins` 컬렉션을 만들고 그 계정의 UID를 문서 ID로 하는 문서를 추가합니다(내용은 비워도 됩니다). 서비스 계정 키가 있으면 `ADMIN_EMAIL=... npm run create-admin`으로도 됩니다.
4. 콘솔의 Authentication > Templates 에서 인증 메일·비밀번호 재설정 메일의 문구와 발신자 이름을 한국어로 바꿉니다.

알아 둘 점:

- **색인**: 에뮬레이터는 복합 색인 없이도 쿼리가 돌기 때문에 `firestore.indexes.json`이 충분한지는 실제 프로젝트에서만 확인됩니다. 부족하면 그 화면에서 오류가 나고 브라우저 콘솔에 색인을 만드는 링크가 나옵니다.
- **무료 요금제 한도**: Firestore 읽기 하루 5만 건, 쓰기 2만 건입니다. 연구자 화면은 열 때마다 자기 연구의 참여 기록과 대기풀 전체를 읽으므로(대기풀 300명 + 참여 기록 수백 건), 연구자가 하루 수십 번 화면을 열면 한도에 가까워집니다. 한도를 넘으면 그날은 읽기가 막힙니다.
- **저장 시 암호화**: 이름·연락처·설문 응답은 Firestore에 평문으로 저장됩니다(Google의 기본 저장 암호화만 적용). 프로젝트 소유자·편집자 권한이 있는 사람은 콘솔에서 내용을 볼 수 있으니 콘솔 권한을 최소한으로 관리해야 합니다.
- **서버가 없어서 화면이 대신 하는 일**: 모집 기간이 지난 연구의 마감과 완료 인원 집계는 담당 연구자가 화면을 열 때, 첫 화면 통계는 관리자가 화면을 열 때 갱신됩니다. 자동 리마인더와 방문 하루 전 안내는 동작하지 않습니다.

## 폴더 구조

```
web/                     화면 소스
  main.js                화면 코드(그리기와 동작 연결)
  data.js                Firebase 연결: 역할별 데이터 읽기, 대기풀 집계, 동작(쓰기)
  domain.js              매칭·검증 규칙
  firebase-config.js     프로젝트 설정(공개 식별자), 에뮬레이터 전환
public/                  배포되는 정적 파일. app.js는 빌드 결과물(npm run build)
firestore.rules          보안 규칙 ← 접근 통제의 전부
firestore.indexes.json   복합 색인
firebase.json            배포·에뮬레이터 설정
scripts/                 시연 데이터(에뮬레이터 전용), 관리자 지정
test/                    규칙 테스트, 매칭·검증 테스트
```

학과 목록, 관심 분야, 연구 유형 같은 선택지는 `web/domain.js`와 `web/main.js` 맨 위의 상수를 함께 고칩니다. 규칙에도 신분·연구 유형 목록이 들어 있으니 같이 고쳐야 합니다.

## 운영 전에 해야 할 일

1. **IRB·개인정보 보호책임자 검토.** 대기풀 운영 방식, 가입 화면의 수집·이용 동의 문구, 전자동의 방식(성명 입력 서명), 동의서를 플랫폼이 보관하는 구조, 확인된 연구자가 대기풀 매칭 정보를 읽을 수 있는 점.
2. **외부 클라우드 보관 검토.** 참여자 정보가 Google Cloud(Firebase)에 평문으로 저장됩니다. 개인정보 처리 위탁에 해당하므로 처리방침 기재와 학교 승인이 필요합니다.
3. **학교 로고 사용 승인.** 화면에 한신대학교 엠블럼과 로고가 들어 있습니다.
4. **보상 발송 주체 결정.** 지금은 연구윤리지원팀이 상품권을 직접 보내는 구조입니다.
5. **Firebase 콘솔 권한 관리, 백업, 보관 기간이 지난 자료의 폐기 절차.** 자동 폐기는 없습니다.

## 아직 없는 것

- 이메일·문자 알림, 자동 리마인더(Functions와 발송 계정이 필요합니다).
- 본인 확인은 이메일 인증뿐입니다. 학외 참여자는 한 사람이 여러 계정을 만들 수 있습니다.
- 가입 후 이름·휴대전화·출생연도·신분을 고치는 화면.
- 종단 연구의 회차별 일정, 상담 프로그램의 회기별 출석 관리. 한 번의 예약과 한 번의 설문만 다룹니다.
- 승인된 연구의 수정 요청 절차, 연구자 계정 정지·탈퇴, 관리자 2단계 인증.
- 문의 본문의 연락처 자동 차단, 문의 횟수 제한(신고로 대응).
